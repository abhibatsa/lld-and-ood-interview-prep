# YAGNI Principle

**Y**ou **A**ren't **G**onna **N**eed **I**t — don't build flexibility for
a requirement that doesn't exist yet.

## Key points
- The most common way candidates over-engineer an LLD answer: adding a
  plugin architecture, config-driven everything, or three layers of
  abstraction for a requirement that only needed one class
- Directly in tension with design patterns — patterns solve *real*
  flexibility needs; YAGNI says don't invent needs to justify using a
  pattern
- In an interview, if you can't name the specific future requirement a
  piece of flexibility protects against, cut it

**Remember:** the strongest LLD answers are often *simpler* than
candidates expect, not more elaborate. Complexity has to earn its place.
